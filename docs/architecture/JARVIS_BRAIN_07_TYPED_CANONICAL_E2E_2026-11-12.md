## Production execution path

- The real typed `brain_entry.prepare → brain_entry.handoff → goal_resolver.resolve` CREATE path calls `canonical_goal_flow.try_create` for typed text only; no regex intent classifier is added. Unadmitted/effectful plans retain their established legacy permissioned path.
- The **existing** `task_agents._SYSTEM` task-graph planner returns its validated task DAG. The adapter accepts only a static manifest-verified read-only `task.research` or `task.account` first attempt. Only research nodes may depend on previously proven task nodes, matching the existing canonical scheduler lane. It validates full tool inputs. Planner JSON is not execution authorization.
- Core publishes a born-canonical, already reducer-accepted GoalState/`goal_plan` in one file via `goal_state_compat.create_canonical_planned_goal`, then publishes a matching queued ExecutionRecord under the existing `goal_job_control.locked` control lock and does **not** change `latest.json`. Two separate files are NOT an atomic transaction; if a write is missing, existing scheduler readiness rejects the incomplete pair. An owner/request ID is checked **before** invoking the DAG planner, and checked again under the same per-job control lock after planning so concurrent duplicate requests still cannot publish a second attempt. An identity collision or half-published pair fails closed without a second model call.
- The **one existing** `task_queue.start` scheduler discovers and dispatches offers via `canonical_scheduler_dispatch.execute_offer`. It does not adopt mutable foreground profile context, grant permissions, auto-retry uncertain effects or hold a global execution lock across provider calls.
- On successful worker projection the scheduler supplies a completion wake. `canonical_plan_evidence.certify_projected_plan` verifies **all** current-plan accepted projected outputs and domain evidence. A separate existing goal-executor semantic `complete` proposal is checked against *exactly* those node IDs and the existing `completion_policy` domain gate. Only deterministic Core `set_state(done)` CAS through `goal_state_compat.commit_verified_goal_completion` (fresh proof/plan/journal checks) can close the global goal.
- Written output uses `event_channels.deliver`, which looks up the owning registered user profile. The visible text is rendered **before** the Core completion CAS and persisted in the same ExecutionRecord as `_canonical_delivery='reserved'` before external fanout. The event has a stable `canonical:<job_id>` ID. After successful UI send it is marked `delivered`. Neither state proves that the user **viewed** the content, and sending is **at most once automatically**, not transactional exactly-once. A crash between Core CAS and journal write remains a separate two-file recovery gap; two competing worker wakes are coalesced without a new scheduler.
- Explicit manual recovery: the background acknowledgement includes the owner-scoped job ID and exact command `hedef sonucu <16-hex-job-id>`. The engine loop routes this bounded **read-only** ID request ahead of Brain/model planning. `canonical_goal_flow.read_completed_result` requires matching owner + Core semantic-completion terminal state + done ExecutionRecord and verifies every projected WorkerResult's original accepted manifest/input/output hash/audit using the existing projector in terminal-read mode. It displays the persisted result (or an older verified journal's render fallback) without triggering model, Scheduler, worker, notification or mutation of the delivery marker. Foreign, unknown, incomplete and tampered IDs fail closed. This is an explicit pull-based recovery path, **not** automatic replay or receipt acknowledgment.
